# Amazon S3 Complete Guide & Reference

## 1. Core Concepts & Static Website Hosting

* **Static Web Hosting:** Amazon S3 supports hosting static websites. It serves static assets such as:
* HTML files and image files
* Client-side scripts
* Video and sound files
*(Note: Dynamic content like server-side scripts or databases are not supported directly by S3).*


* **CORS (Cross-Origin Resource Sharing):** Allows web applications loaded in one domain to interact with resources in another S3 bucket.
```json
[
    {
        "AllowedHeaders": ["*"],
        "AllowedMethods": ["GET", "HEAD"],
        "AllowedOrigins": ["*"],
        "ExposeHeaders": []
    }
]

```

## 2. Storage Classes & Cost Optimization

Choosing the right storage class helps balance performance and cost.

* **S3 Standard:** Designed for frequently accessed data (default storage class).
* **S3 Standard-Infrequent Access (S3 Standard-IA):** Ideal for data that is accessed less frequently, but requires rapid access when needed.
* **S3 One Zone-Infrequent Access (S3 One Zone-IA):** Stores data in a single Availability Zone. Cost-effective for easily re-creatable data or secondary backups.
* **S3 Glacier Deep Archive:** The lowest-cost storage class designed for long-term retention (e.g., 7–10 years) for data accessed rarely or once a year.

---

## 3. Data Protection & Security

* **Server-Side Encryption:** Protects data at rest by encrypting it on the server before it is saved to disks.
* **Client-Side Encryption:** Encrypts data on the client side *before* it is uploaded to Amazon S3 (protecting data in transit and at rest).
* **IAM Roles & Access Policies:** Grants specific permissions to users, services, or cross-account access (e.g., using roles like `CafeRole` with granular actions like `s3:ListBucket`, `s3:ReplicateObject`, etc.).

---

## 4. Lifecycle Policies & Versioning

* **Amazon S3 Versioning:** Keeps multiple variants of an object in the same bucket.
* **Cost implication:** You are charged based on the total amount of storage you use. Storing multiple versions increases storage consumption and cost.
* Deleting an object creates a *delete marker* rather than permanently removing it, unless specific versions are targeted.


* **Lifecycle Policies:** Automates the transition of objects between storage classes or handles their expiration/deletion.
* Example rule: Transition noncurrent object versions to **S3 Standard-IA** after 30 days, and permanently delete previous versions after 365 days.



---

## 5. Replication (Cross-Region Replication - CRR)

* **Definition:** Automatically replicates objects across S3 buckets located in different AWS Regions for disaster recovery and compliance.
* **Key Behaviors:**
* Requires **Versioning** to be enabled on both source and destination buckets.
* By default, setting up replication does *not* migrate existing objects unless explicitly configured.
* Updates, new uploads, and changes trigger automatic replication; simple read/download requests or standard deletions do not replicate delete operations in the same way unless configured via version markers.



---

## 6. Performance & Optimization Features

* **Amazon S3 Transfer Acceleration:** Utilizes AWS Edge Locations and optimized network paths to speed up long-distance data transfers into S3 buckets.
* **Amazon S3 Multipart Uploads:** Allows you to upload a single large object (100 MB to gigabytes) as a set of parts in parallel, enhancing throughput and making recovery from network interruptions more efficient.
